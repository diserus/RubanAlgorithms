# Алгоритм Форда — Беллмана

## Постановка задачи

Дан взвешенный граф из `n` вершин. Стоимость перехода из `v_i` в `v_j` задаётся матрицей `C`, где `C[i][j] = C(v_i, v_j)`. Если ребра между вершинами нет, то `C[i][j] = ∞`. Для каждой вершины `C[i][i] = 0`.

Выделена стартовая вершина `v0`. Требуется найти минимальную стоимость перехода из `v0` в каждую вершину графа.

Граф может быть ориентированным или неориентированным:

- ориентированный — матрица `C` несимметрична;
- неориентированный — `C[i][j] = C[j][i]`, матрица симметрична.

Алгоритм работает и с отрицательными весами, но только если в графе нет достижимого цикла отрицательного веса.

## Идея алгоритма

Алгоритм относится к методам поиска транзитивного замыкания: значения стоимостей пересчитываются до тех пор, пока массив не стабилизируется.

`D[k][i]` — минимальная стоимость переезда из `v0` в `v_i` на `k`-м шаге. Фактически после `k` проходов это минимальная стоимость пути, использующего не более `k` рёбер.

На каждом шаге для каждой вершины `i` перебираются все возможные предыдущие вершины `j`: берётся уже известная стоимость `D[k][j]` и добавляется стоимость ребра `C[j][i]`. Из всех вариантов выбирается минимум.

Когда очередной массив `D` совпал с предыдущим, дальнейшие пересчёты ничего не изменят — достигнута стабилизация, расстояния найдены.

## Обозначения

| Обозначение | Смысл |
|---|---|
| `n` | количество вершин графа |
| `v0` | стартовая вершина |
| `v_i`, `v_j` | произвольные вершины графа |
| `C[i][j]` | стоимость перехода `C(v_i, v_j)`; `∞`, если ребра нет |
| `D[k][i]` | стоимость переезда из `v0` в `v_i` на `k`-м шаге |
| `k` | номер шага (прохода) |
| `INF` | бесконечность в коде (`float("inf")`) |

## Формула пересчёта

Начальный массив задаётся так:

```
D[0] = (0, ∞, ∞, ..., ∞)
```

Нулевой элемент соответствует `v0`, остальные вершины пока недостижимы.

Пересчёт выполняется по формуле (3.1) методички:

```
D[k+1](i) = min_j ( D[k](j) + C(j, i) )
```

где `j` пробегает все вершины графа.

Все значения нового шага считаются по массиву предыдущего шага `D[k]`, а не по уже частично обновлённому `D[k+1]`. Это важно для соответствия методичке: иначе за один проход вершина могла бы улучшиться несколько раз.

Условие остановки:

```
D[k+1] == D[k]
```

## Алгоритм по шагам

1. Заполнить `D[0]`: `D[0][v0] = 0`, остальные элементы — `∞`.
2. Для каждой вершины `i` вычислить `D[k+1](i) = min_j (D[k](j) + C[j][i])`.
3. Сравнить новый массив с предыдущим.
4. Если массивы совпали — стабилизация, вернуть `D[k+1]`.
5. Иначе увеличить `k` и повторить с шага 2.
6. Если после `n` проходов стабилизации нет — в графе есть цикл отрицательного веса.

## Пример из методички

Граф с рис. 3.5: 5 вершин, неориентированный, все веса положительные.

Матрица стоимостей:

```
C = [
    [ 0,  25,  15,   7,   2],
    [25,   0,   6, INF, INF],
    [15,   6,   0,   4, INF],
    [ 7, INF,   4,   0,   3],
    [ 2, INF, INF,   3,   0],
]
```

### Шаг 1

```
D[1](0) = min(0+0,  ∞+25, ∞+15, ∞+7,  ∞+2)  = 0
D[1](1) = min(0+25, ∞+0,  ∞+6,  ∞+∞,  ∞+∞) = 25
D[1](2) = min(0+15, ∞+6,  ∞+0,  ∞+4,  ∞+∞) = 15
D[1](3) = min(0+7,  ∞+∞,  ∞+4,  ∞+0,  ∞+3) = 7
D[1](4) = min(0+2,  ∞+∞,  ∞+∞,  ∞+3,  ∞+0) = 2
```

```
D[1] = (0, 25, 15, 7, 2)
```

### Шаг 2

```
D[2](1) = min(0+25, 25+0, 15+6, 7+∞, 2+∞) = 21
D[2](2) = min(0+15, 25+6, 15+0, 7+4, 2+∞) = 11
D[2](3) = min(0+7,  25+∞, 15+4, 7+0, 2+3) = 5
D[2](4) = min(0+2,  25+∞, 15+∞, 7+3, 2+0) = 2
```

```
D[2] = (0, 21, 11, 5, 2)
```

### Все шаги

| `k` | `D[k](0)` | `D[k](1)` | `D[k](2)` | `D[k](3)` | `D[k](4)` | Примечание |
|---|---|---|---|---|---|---|
| 0 | 0 | ∞ | ∞ | ∞ | ∞ | начальный массив |
| 1 | 0 | 25 | 15 | 7 | 2 | |
| 2 | 0 | 21 | 11 | 5 | 2 | |
| 3 | 0 | 17 | 9 | 5 | 2 | |
| 4 | 0 | 15 | 9 | 5 | 2 | |
| 5 | 0 | 15 | 9 | 5 | 2 | стабилизация |

Кратчайшие расстояния от `v0`:

| Вершина | Расстояние | Кратчайший маршрут |
|---|---|---|
| `v0` | 0 | — |
| `v1` | 15 | `v0 → v2` (15) или `v0 → v4 → v3 → v2 → v1` (2+3+4+6) |
| `v2` | 9 | `v0 → v4 → v3 → v2` (2+3+4) |
| `v3` | 5 | `v0 → v4 → v3` (2+3) |
| `v4` | 2 | `v0 → v4` (2) |

Стоимости по шагам для каждой вершины (рис. 3.6 методички):

```
v0: (0, 0, 0, 0, 0, 0)
v1: (∞, 25, 21, 17, 15, 15)
v2: (∞, 15, 11, 9, 9, 9)
v3: (∞, 7, 5, 5, 5, 5)
v4: (∞, 2, 2, 2, 2, 2)
```

## Почему алгоритм работает

После `k` проходов `D[k][i]` равна минимальной стоимости пути из `v0` в `v_i`, содержащего не более `k` рёбер.

Доказательство по индукции:

- при `k = 0` путь нулевой длины возможен только в `v0`, поэтому `D[0] = (0, ∞, ..., ∞)`;
- любой путь не более чем из `k` рёбер либо содержит не более `k-1` ребра (его стоимость уже учтена в `D[k-1][i]`, так как `C[i][i] = 0`), либо оканчивается ребром `j → i`, где префикс до `j` содержит не более `k-1` ребра. Перебор всех `j` в формуле как раз покрывает второй случай.

Если в графе нет циклов отрицательного веса, кратчайший путь можно выбрать без повторяющихся вершин. Такой путь содержит не более `n-1` рёбер, поэтому после `n-1` проходов все расстояния уже минимальны. Ещё один проход нужен, чтобы убедиться в стабилизации. Отсюда `l ≤ n`, где `l` — число проходов.

Стабилизация необратима: если `D[k+1] = D[k]`, то и все следующие массивы будут такими же, потому что пересчёт — детерминированная функция от предыдущего массива.

## Цикл отрицательного веса

Если в графе есть достижимый цикл отрицательного веса, то стоимость пути можно уменьшать неограниченно, проходя цикл снова и снова. Кратчайшие расстояния в этом случае не определены.

Признак в реализации: после `n` проходов массив всё ещё изменяется. Значит, для некоторой вершины найден маршрут из `n` рёбер, который дешевле всех маршрутов не более чем из `n-1` ребра. В маршруте из `n` рёбер при `n` вершинах есть повторяющаяся вершина, то есть цикл. Если бы цикл был неотрицательным, его можно было бы убрать и получить маршрут без повторов не дороже исходного — противоречие. Следовательно, цикл отрицательный.

В этом случае функция возвращает `negative_cycle = True`, а значения `D` нельзя использовать как расстояния.

Важно: в неориентированном графе любое отрицательное ребро `u — v` образует цикл `u → v → u` отрицательного веса. Поэтому отрицательные веса имеют смысл только в ориентированном графе.

## Сложность

Один проход:

- внешний цикл по шагам;
- цикл по вершинам `i` — `n` итераций;
- внутренний цикл поиска минимума по `j` — `n` итераций.

Итого `n²` операций на проход. Число проходов `l ≤ n`:

```
T(n) = l · n · n
2n² ≤ T(n) ≤ n³
```

- худший случай — `O(n³)`;
- лучший случай — `O(n²)` (стабилизация за два прохода);
- память — `O(n²)` под матрицу `C` и историю `D` (сам алгоритм может обойтись `O(n)` для текущего массива, но реализация хранит все шаги для вывода).

В классической реализации со списком рёбер сложность была бы `O(n · m)`, где `m` — число рёбер. Матричная версия из методички перебирает все пары вершин, поэтому получается `O(n³)`.

## Сравнение с алгоритмом Дейкстры

| Свойство | Форд — Беллман | Дейкстра |
|---|---|---|
| Отрицательные веса | да | нет |
| Цикл отрицательного веса | обнаруживается | не поддерживается |
| Сложность (матричная версия) | `O(n³)` | `O(n²)` |
| Идея | пересчёт до стабилизации | жадно выбирается ближайшая вершина |

Алгоритм Дейкстры быстрее, но требует неотрицательных стоимостей переходов.
