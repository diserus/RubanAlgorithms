# Полубыстрое и быстрое преобразование Фурье

Гайд по [`semi_fast_furie.py`](semi_fast_furie.py): как работает полубыстрое
преобразование Фурье (ППФ), как работает быстрое преобразование Фурье (БПФ),
чем они отличаются и что означает каждая переменная в коде.

Всё написано максимально простым языком: сначала идея, потом формула, потом
пример с числами, потом код и разбор переменных.

> Смежная тема: **[гайд по свёртке](CONVOLUTION.md)** — как перемножать массивы
> через преобразование Фурье.

---

## 1. Самое главное за 30 секунд

Есть три способа посчитать дискретное преобразование Фурье (ДПФ):

| Способ | Когда можно применять | Сколько умножений |
|---|---|---|
| Обычное ДПФ | для любого `N` | `N²` |
| ППФ | если `N = p1 · p2` | `N · (p1 + p2)` |
| БПФ | если `N = 2^r` | `N · log₂N` |

Чем больше `N`, тем важнее разница. Например, для `N = 4096`:

```
ДПФ:  4096²          = 16 777 216 умножений
ППФ:  4096 · (64+64) =    524 288 умножений
БПФ:  4096 · 12      =     49 152 умножения
```

БПФ делает в 341 раз меньше умножений, чем обычное ДПФ, а ППФ — в 32 раза
меньше. ППФ — промежуточный вариант: заметно быстрее ДПФ, но медленнее БПФ.

**ППФ и БПФ считают одно и то же ДПФ.** Отличаются только порядком вычислений,
поэтому результаты у них совпадают (с точностью до погрешности округления).

---

## 2. Что такое ДПФ

Дискретное преобразование Фурье берёт массив из `N` чисел и превращает его в
массив из `N` комплексных коэффициентов:

```
X[k] = (1/N) · Σ f[n] · e^(-2πi·k·n/N),     k = 0..N-1
```

Здесь:

- `f[n]` — входной массив (сигнал);
- `X[k]` — выходной массив (спектр);
- `n` — номер элемента во входе (время);
- `k` — номер коэффициента в спектре (частота);
- `i` — мнимая единица, `i² = -1`;
- `e^(i·φ) = cos(φ) + i·sin(φ)` — поворот на угол `φ` на комплексной плоскости.

Обратное преобразование возвращает сигнал обратно:

```
f[n] = Σ X[k] · e^(+2πi·k·n/N)
```

Обратите внимание: **у прямого преобразования есть множитель `1/N`, у
обратного его нет.** Так принято во всём проекте (так же устроены `dft` и
`idft` в [`furie.py`](furie.py)).

Из-за этого при сравнении с NumPy нужно помнить:

```python
np.fft.fft(f) / N          # совпадает с нашим прямым ДПФ
N * np.fft.ifft(X)         # совпадает с нашим обратным ДПФ
```

### Пример для `N = 2`

Возьмём `f = [1, 2]`. Тогда:

```
X[0] = (1/2) · (1 + 2)       = 1.5
X[1] = (1/2) · (1 + 2·(-1))  = -0.5
```

Получили `X = [1.5, -0.5]`. Обратное преобразование:

```
f[0] = 1.5 + (-0.5) = 1
f[1] = 1.5 - (-0.5) = 2
```

Всё вернулось.

## 3. Обозначения, которые встречаются дальше

| Обозначение | Смысл |
|---|---|
| `N` | длина массива |
| `f[n]` | входной сигнал, `n = 0..N-1` |
| `X[k]` | спектр, `k = 0..N-1` |
| `i` | мнимая единица |
| `p1`, `p2` | множители `N`: `N = p1 · p2` (только для ППФ) |
| `r` | степень двойки: `N = 2^r` (только для БПФ) |
| `s` | номер шага БПФ, `s = 0..r-1` |
| `j1`, `j2` | «цифры» номера входа `n` в ППФ (в БПФ — `j1..jr`) |
| `k1`, `k2` | «цифры» номера выхода `k` в ППФ (в БПФ — `k1..kr`) |
| `A^(s)` | массив после `s` шагов БПФ |
| `C = 5` | условная стоимость одного комплексного умножения |

В коде используются комплексные числа из [`mycomplex.py`](mycomplex.py):

- `z.real` — действительная часть;
- `z.imag` — мнимая часть;
- `Complex(a, b)` — создать число `a + b·i`.

# Часть I. Полубыстрое преобразование Фурье (ППФ)

## 4. Идея ППФ

Пусть `N = p1 · p2`. Запишем номер входа `n` и номер выхода `k` двумя числами:

```
n = j2 + p2 · j1        j1 = 0..p1-1,  j2 = 0..p2-1
k = k1 + p1 · k2        k1 = 0..p1-1,  k2 = 0..p2-1
```

Проще говоря, раскладываем одномерный массив в таблицу `p1 × p2`:

- `j1` — номер строки;
- `j2` — номер столбца;
- `k1` — номер строки результата;
- `k2` — номер столбца результата.

Для `N = 8`, `p1 = 2`, `p2 = 4` вход выглядит так:

```
              j2=0   j2=1   j2=2   j2=3
j1=0:          f0     f1     f2     f3
j1=1:          f4     f5     f6     f7
```

Идея: вместо одной суммы из `N` слагаемых посчитать **две маленькие суммы**:
сначала по столбцам (длина `p1`), потом по строкам (длина `p2`).

## 5. Две формулы ППФ

### Шаг 1 — ДПФ по столбцам

```
A1(k1, j2) = (1/p1) · Σ_{j1=0..p1-1} f[j2 + p2·j1] · e^(-2πi·j1·k1/p1)     (2.3a)
```

Что здесь происходит: для каждого столбца `j2` берём его `p1` элементов
(`f[j2]`, `f[j2+p2]`, …) и считаем от них маленькое ДПФ длины `p1`.
Результат кладём в промежуточный массив `A1`.

### Шаг 2 — ДПФ по строкам с поправкой на фазу

```
X[k1 + p1·k2] = (1/p2) · Σ_{j2=0..p2-1} A1(k1, j2) · e^(-2πi·j2·(k1 + p1·k2)/N)   (2.3b)
```

Теперь для каждой строки `k1` считаем ДПФ длины `p2`, но экспонента зависит не
только от `j2`, но и от номера строки `k1`. Это та самая «поправка на фазу».

Выход сразу получается в правильном порядке: `k = k1 + p1·k2`.

## 6. Пример ППФ для `N = 4`

Возьмём `f = [1, 2, 3, 4]`, `p1 = 2`, `p2 = 2`.

Таблица входа:

```
              j2=0   j2=1
j1=0:           1      2
j1=1:           3      4
```

### Шаг 1: ДПФ по столбцам

Столбец `j2 = 0`: числа `[1, 3]`, длина `p1 = 2`.

```
A1(0, 0) = (1 + 3) / 2 = 2
A1(1, 0) = (1 - 3) / 2 = -1
```

Столбец `j2 = 1`: числа `[2, 4]`.

```
A1(0, 1) = (2 + 4) / 2 = 3
A1(1, 1) = (2 - 4) / 2 = -1
```

Таблица `A1`:

```
              j2=0   j2=1
k1=0:           2      3
k1=1:          -1     -1
```

### Шаг 2: ДПФ по строкам

Строка `k1 = 0`: `[2, 3]`.

```
k2 = 0:  X[0 + 2·0] = X[0] = (2 + 3) / 2 = 2.5
k2 = 1:  X[0 + 2·1] = X[2] = (2 - 3) / 2 = -0.5
```

Строка `k1 = 1`: `[-1, -1]`, но с фазовыми множителями:

```
k2 = 0:  X[1] = (-1 + (-1)·e^(-2πi·1/4)) / 2 = (-1 + i) / 2 = -0.5 + 0.5i
k2 = 1:  X[3] = (-1 + (-1)·e^(-2πi·3/4)) / 2 = (-1 - i) / 2 = -0.5 - 0.5i
```

Итог:

```
X = [2.5, -0.5 + 0.5i, -0.5, -0.5 - 0.5i]
```

Проверим по обычной формуле ДПФ:

```
X[0] = (1+2+3+4)/4 = 2.5
X[1] = (1 - 2i - 3 + 4i)/4 = (-2 + 2i)/4 = -0.5 + 0.5i
X[2] = (1-2+3-4)/4 = -0.5
X[3] = (1 + 2i - 3 - 4i)/4 = (-2 - 2i)/4 = -0.5 - 0.5i
```

Совпало.

## 7. Код прямого ППФ

```python
def half_fast_forward(f, p1, p2):
    N = p1 * p2
    if N != len(f):
        raise ValueError("ППФ: длина массива должна быть равна p1 * p2")
    mul_count = 0

    A1 = [Complex() for _ in range(N)]

    for k1 in range(p1):
        for j2 in range(p2):
            acc = Complex()
            for j1 in range(p1):
                angle = 2.0 * math.pi * (j1 * k1) / p1
                e = Complex(math.cos(-angle), math.sin(-angle))
                e = e * f[j2 + p2 * j1]
                mul_count += 1
                acc = acc + e
            A1[k1 * p2 + j2] = acc * (1.0 / p1)

    A = [Complex() for _ in range(N)]

    for k1 in range(p1):
        for k2 in range(p2):
            acc = Complex()
            for j2 in range(p2):
                angle = 2.0 * math.pi * (j2 / N) * (k1 + p1 * k2)
                e = Complex(math.cos(-angle), math.sin(-angle))
                e = e * A1[k1 * p2 + j2]
                mul_count += 1
                acc = acc + e
            A[k1 + p1 * k2] = acc * (1.0 / p2)

    return A, mul_count
```

### За что отвечает каждая переменная

| Переменная | Что означает |
|---|---|
| `f` | входной массив длины `N` (числа или `Complex`) |
| `p1` | первый множитель: число строк таблицы |
| `p2` | второй множитель: число столбцов таблицы |
| `N` | `p1 * p2`, длина массива |
| `mul_count` | счётчик комплексных умножений (каждое слагаемое — одно умножение) |
| `A1` | промежуточный массив `A1(k1, j2)` после шага 1 |
| `k1` | номер строки результата, `0..p1-1` |
| `j2` | номер столбца, `0..p2-1` |
| `acc` | накопитель суммы для одной формулы |
| `j1` | номер строки входа, `0..p1-1` |
| `angle` | угол `2π·j1·k1/p1` |
| `e` | комплексное слагаемое: `e^(-i·angle) · f[...]` |
| `A` | итоговый спектр `X[k]` |
| `k2` | номер «столбца» результата, `0..p2-1` |
| `f[j2 + p2·j1]` | входной элемент с номером `n = j2 + p2·j1` |
| `A[k1 + p1·k2]` | выходной элемент с номером `k = k1 + p1·k2` |
| `_` | счётчик в генераторе списка; сам по себе не нужен |

Почему `A1` хранится по индексу `k1 * p2 + j2`: это просто «одномерная
упаковка» таблицы `p1 × p2` по строкам.

`mul_count` считает только умножения внутри сумм. Умножения на `1/p1` и
`1/p2` в счётчик не входят — это нормировка, а не слагаемые формул.

## 8. Обратное ППФ

Правило из методички: **те же формулы**, но

1. в экспоненте знак меняется с `-` на `+`;
2. множители `1/p1` и `1/p2` убираются.

То есть:

```
A1(k1, j2) = Σ_{k2} X[k1 + p1·k2] · e^(+2πi·j2·(k1 + p1·k2)/N)
f[j2 + p2·j1] = Σ_{k1} A1(k1, j2) · e^(+2πi·j1·k1/p1)
```

Порядок проходов обратный: сначала раскручиваем шаг 2 (сумма по `k2`), потом
шаг 1 (сумма по `k1`).

### Пример

Возьмём `X = [2.5, -0.5+0.5i, -0.5, -0.5-0.5i]` из примера выше.

После первого обратного прохода (сумма по `k2`) получаем:

```
A1 = [2, 3, -1, -1]
```

Второй проход (сумма по `k1`) для `j1 = 0`:

```
f[j2] = A1(0, j2) + A1(1, j2)
```

То есть `f[0] = 2 + (-1) = 1`, `f[1] = 3 + (-1) = 2`.

Для `j1 = 1` знак множителя меняется:

```
f[2] = 2 - (-1) = 3
f[3] = 3 - (-1) = 4
```

Получили исходное `f = [1, 2, 3, 4]`.

### Код и переменные обратного ППФ

```python
def half_fast_backward(A, p1, p2):
    N = p1 * p2
    if N != len(A):
        raise ValueError("ППФ: длина массива должна быть равна p1 * p2")
    mul_count = 0

    A1 = [Complex() for _ in range(N)]

    for k1 in range(p1):
        for j2 in range(p2):
            acc = Complex()
            for k2 in range(p2):
                angle = 2.0 * math.pi * (j2 / N) * (k1 + p1 * k2)
                e = Complex(math.cos(angle), math.sin(angle))
                e = e * A[k1 + p1 * k2]
                mul_count += 1
                acc = acc + e
            A1[k1 * p2 + j2] = acc

    f = [0.0] * N
    for j1 in range(p1):
        for j2 in range(p2):
            acc = Complex()
            for k1 in range(p1):
                angle = 2.0 * math.pi * (j1 * k1) / p1
                e = Complex(math.cos(angle), math.sin(angle))
                e = e * A1[k1 * p2 + j2]
                mul_count += 1
                acc = acc + e
            f[j2 + p2 * j1] = acc.real

    return f, mul_count
```

| Переменная | Что означает |
|---|---|
| `A` | входной спектр `X[k]` |
| `p1`, `p2` | те же множители, что и при прямом преобразовании |
| `N` | `p1 * p2` |
| `mul_count` | счётчик умножений |
| `A1` | промежуточный массив после обратного шага 2 |
| `k1` | номер строки, `0..p1-1` |
| `j2` | номер столбца, `0..p2-1` |
| `acc` | накопитель суммы |
| `k2` | номер столбца спектра, `0..p2-1` |
| `angle` | угол `2π·j2·(k1 + p1·k2)/N` |
| `e` | слагаемое `e^(+i·angle) · X[...]` |
| `f` | результат — массив действительных чисел |
| `j1` | номер строки результата, `0..p1-1` |
| `A[k1 + p1·k2]` | элемент спектра с номером `k = k1 + p1·k2` |
| `f[j2 + p2·j1]` | элемент результата с номером `n = j2 + p2·j1` |

`acc.real` берётся потому, что исходный сигнал вещественный: мнимая часть в
результате должна сократиться до нуля (остаётся только погрешность).

## 9. Трудоёмкость ППФ

На шаге 1:

```
p2 столбцов × p1 выходов × p1 слагаемых = p1² · p2
```

На шаге 2:

```
p1 строк × p2 выходов × p2 слагаемых = p1 · p2²
```

Итого:

```
T(N) = p1²·p2 + p1·p2² = p1·p2·(p1 + p2) = N·(p1 + p2)
```

Если выбрать `p1 ≈ p2 ≈ √N`, получится:

```
T(N) = 2·N^(3/2) = O(N^(3/2))
```

**Важно:** выигрыш появляется только при удачном разложении. Если взять
`p1 = 1`, `p2 = N`, то `T = N·(1+N) ≈ N²` — никакого ускорения нет.
Поэтому `p1` и `p2` надо брать как можно ближе друг к другу.

# Часть II. Быстрое преобразование Фурье (БПФ)

## 10. Идея БПФ

БПФ — это то же самое разложение, что и в ППФ, но применённое много раз.

Пусть `N = 2^r`. Запишем номера `n` и `k` в двоичном виде:

```
n = j_r + 2·j_(r-1) + ... + 2^(r-1)·j_1
k = k_1 + 2·k_2 + ... + 2^(r-1)·k_r
```

Здесь у номера входа `j_1` — самый старший бит, а у номера выхода `k_1` —
самый младший (так эти суммы определены в методичке).

При этом в массиве `A^(s)` индексы `(k1..ks, j(s+1)..jr)` записываются в
позицию слева направо: `k1` попадает в старший бит позиции, `jr` — в младший.
Из-за этого готовые коэффициенты внутри массива лежат в бит-реверсном порядке,
и в конце их нужно переставить (об этом ниже).

Вместо одного разложения на два множителя делаем `r` шагов. На каждом шаге
массив `A^(s)` превращается в `A^(s+1)`, и на каждом шаге появляется
множитель `1/2`. После `r` шагов накопится `1/2^r = 1/N` — как и должно быть
в формуле ДПФ.

## 11. Формула (2.4)

```
A^(s+1)(k1..ks, k(s+1), j(s+2)..jr) =
    1/2 · Σ_{j(s+1)=0..1}
        e^(-2πi·j(s+1)·K / 2^(s+1)) ·
        A^(s)(k1..ks, j(s+1), j(s+2)..jr)
```

где

```
K = k1 + 2·k2 + ... + 2^s·k(s+1)
```

Смысл формулы простой:

- уже известны биты `k1..ks`;
- ещё не известны биты `j(s+1)..jr`;
- на шаге `s` мы «фиксируем» очередной бит `k(s+1)`;
- для этого берём два значения `A^(s)` — с `j(s+1) = 0` и с `j(s+1) = 1` —
  и комбинируем их с поворотным множителем.

Для первых шагов формула выглядит так:

```
A^(1)(k1, j2..jr) = 1/2 · Σ_{j1} e^(-2πi·j1·k1/2) · A^(0)(j1, j2..jr)

A^(2)(k1, k2, j3..jr) =
    1/2 · Σ_{j2} e^(-2πi·j2·(2k2 + k1)/4) · A^(1)(k1, j2, j3..jr)

A^(3)(k1, k2, k3, j4..jr) =
    1/2 · Σ_{j3} e^(-2πi·j3·(4k3 + 2k2 + k1)/8) ·
        A^(2)(k1, k2, j3, j4..jr)
```

В конце:

```
A^(r)(k1, k2, ..., kr) = X[k1 + 2·k2 + ... + 2^(r-1)·kr]
```

## 12. «Бабочка» — что реально делает код

На каждом шаге два числа `a` и `b` превращаются в два новых числа. Это
называется «бабочка»:

```
          a ─────────────── (a + w·b) / 2
          
          b ───[ w ]─────── (a - w·b) / 2
```

где

```
a = A^(s)(..., j(s+1) = 0, ...)
b = A^(s)(..., j(s+1) = 1, ...)
w = e^(-2πi·K_s / 2^(s+1))
K_s = k1 + 2·k2 + ... + 2^(s-1)·ks
```

Почему для второго выхода стоит минус: при `k(s+1) = 1` в показателе
экспоненты добавляется `2^s`, и

```
e^(-2πi·(K_s + 2^s) / 2^(s+1)) = -e^(-2πi·K_s / 2^(s+1)) = -w
```

Отсюда и получаются два выражения `a + w·b` и `a - w·b`.

## 13. Пример БПФ для `N = 4`

Возьмём тот же `f = [1, 2, 3, 4]`, `r = 2`.

### Шаг `s = 0` (первый)

`K_s = 0`, поэтому `w = 1`.

```
k1 = 0:  A^(1)(0, j2) = (f[j2] + f[j2+2]) / 2
k1 = 1:  A^(1)(1, j2) = (f[j2] - f[j2+2]) / 2
```

Получаем тот же промежуточный массив, что и в ППФ:

```
A^(1) = [2, 3, -1, -1]
```

(здесь он записан подряд: `A^(1)(0,0) = 2`, `A^(1)(0,1) = 3`,
`A^(1)(1,0) = -1`, `A^(1)(1,1) = -1`).

### Шаг `s = 1` (второй)

Для `k1 = 0`: `K_s = 0`, `w = 1`.

```
A^(2)(0, 0) = (2 + 3) / 2 = 2.5
A^(2)(0, 1) = (2 - 3) / 2 = -0.5
```

Для `k1 = 1`: `K_s = 1`, `w = e^(-2πi/4) = -i`.

```
A^(2)(1, 0) = (-1 + (-i)·(-1)) / 2 = (-1 + i) / 2 = -0.5 + 0.5i
A^(2)(1, 1) = (-1 - (-i)·(-1)) / 2 = (-1 - i) / 2 = -0.5 - 0.5i
```

Итог по формуле `X[k1 + 2·k2]`:

```
X[0] = A^(2)(0, 0) = 2.5
X[2] = A^(2)(0, 1) = -0.5
X[1] = A^(2)(1, 0) = -0.5 + 0.5i
X[3] = A^(2)(1, 1) = -0.5 - 0.5i
```

Получили тот же спектр, что и ППФ.

## 14. Раскладка массива и бит-реверс

В коде массив `A^(s)` одномерный. Позиция элемента — это набор индексов
`(k1..ks, j(s+1)..jr)`, записанных подряд битами.

Пример для `N = 8`, `r = 3`, шаг `s = 1`, `k = 1` (то есть `k1 = 1`). Позиция
состоит из битов `(k1, j2, j3)`:

```
позиция 4 = 100  →  k1=1, j2=0, j3=0
позиция 6 = 110  →  k1=1, j2=1, j3=0
```

Пара для шага `s = 1` — это позиции, которые отличаются битом `j2`:

- `i0 = 4` — элемент с `j2 = 0`;
- `i1 = 6` — элемент с `j2 = 1`.

В конце после `r` шагов в массиве `A^(r)` на позиции `p` лежит коэффициент
`X[k]`, где `k` — это `p`, прочитанное справа налево (бит-реверс):

```
p:            0  1  2  3  4  5  6  7
k = reverse:  0  4  2  6  1  5  3  7
```

Поэтому в `fast_forward` есть финальная перестановка:

```python
X[k] = A_r[_bit_reverse(k, r)]
```

Она просто расставляет коэффициенты в привычный порядок `X[0], X[1], ...`.

## 15. Код прямого БПФ

```python
def _bit_reverse(value, bits):
    result = 0
    for _ in range(bits):
        result = (result << 1) | (value & 1)
        value >>= 1
    return result


def _forward_steps(A_0, r):
    N = len(A_0)
    A_s = A_0
    mul_count = 0

    for s in range(r):
        A_next = [Complex() for _ in range(N)]

        for k in range(1 << s):
            K_s = _bit_reverse(k, s)
            angle = -2.0 * math.pi * K_s / (1 << (s + 1))
            w = Complex(math.cos(angle), math.sin(angle))

            for j in range(1 << (r - s - 1)):
                i0 = ((2 * k) << (r - s - 1)) | j
                i1 = i0 | (1 << (r - s - 1))
                A_j0 = A_s[i0]
                A_j1 = A_s[i1]
                A_next[i0] = (A_j0 + w * A_j1) * 0.5
                A_next[i1] = (A_j0 - w * A_j1) * 0.5
                mul_count += 2

        A_s = A_next

    return A_s, mul_count


def fast_forward(f):
    N = len(f)
    if N == 0 or N & (N - 1):
        raise ValueError("БПФ: длина массива должна быть степенью двойки")

    r = N.bit_length() - 1

    A_0 = [Complex(v.real, v.imag) if isinstance(v, Complex) else Complex(v) for v in f]
    A_r, mul_count = _forward_steps(A_0, r)

    X = [Complex() for _ in range(N)]
    for k in range(N):
        X[k] = A_r[_bit_reverse(k, r)]

    return X, mul_count
```

### За что отвечает каждая переменная

`_bit_reverse(value, bits)`:

| Переменная | Что означает |
|---|---|
| `value` | число, у которого переставляем биты |
| `bits` | сколько младших бит переставлять |
| `result` | результат перестановки |
| `_` | счётчик цикла; значение счётчика не используется |

Пример: `_bit_reverse(3, 3)` — число `3` это `011` в двоичном виде,
перестановка даёт `110`, то есть `6`.

`_forward_steps(A_0, r)`:

| Переменная | Что означает |
|---|---|
| `A_0` | массив `A^(0)`, то есть исходный сигнал |
| `r` | `log₂(N)`, число шагов |
| `N` | длина массива |
| `A_s` | текущий массив `A^(s)` |
| `mul_count` | счётчик комплексных умножений |
| `s` | номер шага, `0..r-1` |
| `A_next` | новый массив `A^(s+1)` |
| `k` | упакованный набор `(k1..ks)`; его двоичная запись — это уже известные биты `k` |
| `K_s` | сумма `k1 + 2·k2 + ... + 2^(s-1)·ks` |
| `angle` | угол `-2π·K_s / 2^(s+1)` |
| `w` | поворотный множитель `e^(i·angle)` |
| `j` | упакованный набор `(j(s+2)..jr)`; его двоичная запись — оставшиеся неизвестные биты |
| `i0` | позиция элемента с `j(s+1) = 0` |
| `i1` | позиция элемента с `j(s+1) = 1` |
| `A_j0` | значение `A^(s)` в позиции `i0` |
| `A_j1` | значение `A^(s)` в позиции `i1` |
| `A_next[i0]` | новое значение с `k(s+1) = 0` |
| `A_next[i1]` | новое значение с `k(s+1) = 1` |

Как читать `i0` и `i1`:

```
i0 = ((2·k) << (r-s-1)) | j
```

- `2·k` — это биты `(k1..ks)` плюс пока нулевой бит `j(s+1)`;
- сдвиг влево освобождает место для хвоста `(j(s+2)..jr)`;
- `| j` — вписывает хвост;
- `i1` — то же самое, но с битом `j(s+1) = 1`.

`fast_forward(f)`:

| Переменная | Что означает |
|---|---|
| `f` | входной массив |
| `N` | длина массива |
| `r` | `log₂(N)` |
| `A_0` | копия входа в виде массива `Complex` |
| `A_r` | результат после всех шагов (в бит-реверсном порядке) |
| `mul_count` | число умножений |
| `X` | итоговый спектр в обычном порядке |
| `k` | номер частоты, `0..N-1` |
| `v` | элемент входного массива в генераторе списка |
| `_` | счётчик в генераторе списка |

## 16. Обратное БПФ

Правило то же: **те же формулы**, но в экспоненте `+`, множителя `1/2` нет,
шаги идут в обратном порядке.

Если прямой шаг был

```
u = (a + w·b) / 2
v = (a - w·b) / 2
```

то обратный шаг — это решение этой системы относительно `a` и `b`:

```
a = u + v
b = w^(-1)·(u - v)
```

где `w` — прямой поворотный множитель, а `w^(-1)` имеет знак `+` в
экспоненте. Именно это и записано в коде:

```python
A_prev[i0] = A_k0 + A_k1
A_prev[i1] = w * (A_k0 - A_k1)
```

Здесь `A_k0` и `A_k1` — это `u` и `v`, то есть значения с `k(s+1) = 0` и
`k(s+1) = 1`, а `w` уже содержит знак `+`.

### Пример

Возьмём `X = [2.5, -0.5+0.5i, -0.5, -0.5-0.5i]`.

Сначала раскладываем его в бит-реверсном порядке:

```
A^(2) = [X0, X2, X1, X3] = [2.5, -0.5, -0.5+0.5i, -0.5-0.5i]
```

Шаг `s = 1`:

```
k = 0:  w = 1
        a = 2.5 + (-0.5)       = 2
        b = 1 · (2.5 - (-0.5)) = 3

k = 1:  w = e^(+2πi/4) = i
        a = (-0.5+0.5i) + (-0.5-0.5i) = -1
        b = i · [(-0.5+0.5i) - (-0.5-0.5i)] = i·i = -1
```

Для `k = 0` пара — это позиции `0` и `1`, для `k = 1` — позиции `2` и `3`.
Получили `A^(1) = [2, 3, -1, -1]`.

Шаг `s = 0` (пары `0↔2` и `1↔3`, `w = 1`):

```
a = 2 + (-1) = 1       → f[0]
b = 2 - (-1) = 3       → f[2]
a = 3 + (-1) = 2       → f[1]
b = 3 - (-1) = 4       → f[3]
```

Итог: `f = [1, 2, 3, 4]`.

### Код обратного БПФ

```python
def _backward_steps(A_r, r):
    N = len(A_r)
    A_s = A_r
    mul_count = 0

    for s in range(r - 1, -1, -1):
        A_prev = [Complex() for _ in range(N)]

        for k in range(1 << s):
            K_s = _bit_reverse(k, s)
            angle = 2.0 * math.pi * K_s / (1 << (s + 1))
            w = Complex(math.cos(angle), math.sin(angle))

            for j in range(1 << (r - s - 1)):
                i0 = ((2 * k) << (r - s - 1)) | j
                i1 = i0 | (1 << (r - s - 1))
                A_k0 = A_s[i0]
                A_k1 = A_s[i1]
                A_prev[i0] = A_k0 + A_k1
                A_prev[i1] = w * (A_k0 - A_k1)
                mul_count += 2

        A_s = A_prev

    return A_s, mul_count


def fast_backward(X):
    N = len(X)
    if N == 0 or N & (N - 1):
        raise ValueError("БПФ: длина массива должна быть степенью двойки")

    r = N.bit_length() - 1

    A_r = [Complex() for _ in range(N)]
    for position in range(N):
        k = _bit_reverse(position, r)
        A_r[position] = Complex(X[k].real, X[k].imag)

    A_0, mul_count = _backward_steps(A_r, r)

    return [z.real for z in A_0], mul_count
```

| Переменная | Что означает |
|---|---|
| `A_r` | массив `A^(r)`, то есть спектр в бит-реверсной раскладке |
| `r` | `log₂(N)` |
| `N` | длина массива |
| `A_s` | текущий массив на входе шага: сначала `A^(r)`, потом `A^(r-1)` и так далее |
| `mul_count` | счётчик умножений |
| `s` | номер шага, идёт от `r-1` до `0` |
| `A_prev` | получаемый на этом шаге массив `A^(s)` |
| `k` | упакованный набор `(k1..ks)` |
| `K_s` | сумма `k1 + 2·k2 + ... + 2^(s-1)·ks` |
| `angle` | угол `+2π·K_s / 2^(s+1)` |
| `w` | `e^(i·angle)`, то есть обратный поворотный множитель |
| `j` | упакованный набор `(j(s+2)..jr)` |
| `i0`, `i1` | позиции с `k(s+1) = 0` и `k(s+1) = 1` |
| `A_k0`, `A_k1` | значения текущего массива в этих позициях (`u` и `v`) |
| `X` | входной спектр в обычном порядке |
| `A_r` (в `fast_backward`) | тот же спектр, но разложенный по бит-реверсным позициям |
| `position` | позиция в массиве `A_r`, `0..N-1` |
| `k` (в `fast_backward`) | номер частоты, соответствующий позиции |
| `A_0` | результат обратных шагов, то есть исходный сигнал |
| `z` | элемент `A_0` при взятии действительной части |

Обратное БПФ, как и обратное ППФ, возвращает только `.real`: исходный сигнал
предполагается вещественным.

## 17. Трудоёмкость БПФ

На каждом шаге:

```
N/2 «бабочек» × 2 умножения = N умножений
```

Шагов `r = log₂N`, поэтому:

```
T(N) = N · r = N · log₂N
```

В проекте, как и в методичке, считается по два умножения на пару — по одному
на каждый из двух выходов (множители `w` и `-w`). Отсюда `N` умножений на
шаг и `T = C·N·log₂N`. Умножения на `1/2` в счётчик не входят — это
нормировка.

Если не считать умножение на `1` и переиспользовать `w` для обоих выходов
«бабочки», реально нужно `N/2` умножений на шаг, то есть `(N/2)·log₂N`.
Асимптотика от этого не меняется: `O(N log N)`.

## 18. Сравнение ППФ и БПФ

| | ППФ | БПФ |
|---|---|---|
| Ограничение на `N` | `N = p1 · p2` | `N = 2^r` |
| Число шагов | 2 | `r = log₂N` |
| Множитель на шаге | `1/p1`, `1/p2` | `1/2` |
| Трудоёмкость | `N·(p1+p2)` | `N·log₂N` |
| При `p1 ≈ p2 ≈ √N` | `O(N^(3/2))` | `O(N log N)` |
| Порядок результата | сразу правильный | внутри бит-реверсный, потом переставляется |
| Обратное преобразование | знак `+`, без `1/p` | знак `+`, без `1/2` |

ППФ проще для понимания: всего два прохода и обычные вложенные циклы. БПФ
сложнее из-за битовой раскладки, но работает быстрее.

### Числа для `N = 8`

```
ДПФ: 64 умножения
ППФ: 8 · (2 + 4) = 48 умножений
БПФ: 8 · 3      = 24 умножения
```

Демо-программа как раз использует `N = 8`, `p1 = 2`, `p2 = 4`, поэтому ППФ
делает 48 умножений, а БПФ — 24. Оба метода выдают одинаковый спектр.

```bash

```

Программа:

## 20. Как пользоваться в своём коде

```python
from semi_fast_furie import (
    half_fast_forward,
    half_fast_backward,
    fast_forward,
    fast_backward,
)

f = [1.0, 2.0, 3.0, 4.0]

A, ops = half_fast_forward(f, 2, 2)
f2, ops2 = half_fast_backward(A, 2, 2)

X, ops3 = fast_forward(f)
f3, ops4 = fast_backward(X)
```

Обе функции проверяют длину и выбрасывают `ValueError`, если массив не подходит:

```python
ValueError: ППФ: длина массива должна быть равна p1 * p2
ValueError: БПФ: длина массива должна быть степенью двойки
```

Проверка ППФ нужна, чтобы несовпадение `len(f)` и `p1 * p2` не превращалось в
`IndexError: list index out of range` где-то в середине вычислений.

## 21. Как проверить правильность

Самый простой способ — сравнить с NumPy (если он установлен):

```python
import numpy as np
from semi_fast_furie import fast_forward, fast_backward

f = [1.0, 3.0, -2.0, 5.0, 0.0, -1.0, 4.0, -3.0]

X, _ = fast_forward(f)
X_np = np.fft.fft(f) / len(f)

got = np.array([z.real + 1j * z.imag for z in X])
print(np.max(np.abs(got - X_np)))       # примерно 1e-15

f_back, _ = fast_backward(X)
print(np.max(np.abs(np.array(f_back) - np.array(f))))  # примерно 1e-15
```

Для ППФ:

```python
import numpy as np
from semi_fast_furie import half_fast_forward

f = [1.0, 2.0, 3.0, 4.0]
A, _ = half_fast_forward(f, 2, 2)
got = np.array([z.real + 1j * z.imag for z in A])
print(np.max(np.abs(got - np.fft.fft(f) / len(f))))    # примерно 1e-16
```

Расхождение порядка `10⁻¹⁵` — это нормальная погрешность чисел с плавающей
точкой, а не ошибка алгоритма.

## 22. Частые ошибки

| Ошибка | Что будет |
|---|---|
| `len(f) != p1 * p2` в ППФ | `ValueError: ППФ: длина массива должна быть равна p1 * p2` |
| `p1 = 1`, `p2 = N` | ППФ работает как обычное ДПФ, `O(N²)` |
| `p1` и `p2` сильно различаются | нет ускорения относительно ДПФ |
| Длина не степень двойки в БПФ | `ValueError` |
| Забыли множитель `1/N` при сравнении с NumPy | результат в `N` раз больше |
| Забыли `1/2` на шаге БПФ | результат в `N` раз больше |
| Перепутали `n = j2 + p2·j1` и `n = j1 + p1·j2` | неверный порядок элементов |
| Ждём от обратного преобразования комплексный результат | возвращается только `.real` |
| Думаем, что ППФ — это «половина БПФ» | это отдельный алгоритм, название историческое |

## 23. Шпаргалка по индексам

| Что | Формула | Где используется |
|---|---|---|
| Номер входа в ППФ | `n = j2 + p2·j1` | `half_fast_forward`, `half_fast_backward` |
| Номер выхода в ППФ | `k = k1 + p1·k2` | `half_fast_forward`, `half_fast_backward` |
| Биты входа в БПФ | `j1..jr`, `j1` — старший | `A^(0)` |
| Биты выхода в БПФ | `k1..kr`, `k1` — младший | `A^(r)` |
| Сумма в экспоненте | `K = k1 + 2·k2 + ...` | все шаги БПФ |
| Расстояние в паре | `2^(r-s-1)` | `i0`, `i1` |
| Бит-реверс | `k = reverse(p)` | финальная перестановка |
